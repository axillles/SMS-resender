# Чеклист для публикации в App Store

## ✅ Сделано в приложении

- **Блокировка поворота** — только портретная ориентация (iPhone: портрет; iPad: портрет и портрет перевёрнутый).
- **Удаление аккаунта** — в Настройках есть «Delete Account» с подтверждением и очисткой данных.
- **Подписка (In-App Purchase)** — подписка через StoreKit 2, экран пейвола, восстановление покупок.
- **Шифрование** — в Info.plist указано `ITSAppUsesNonExemptEncryption = false` (если не используете своё шифрование — так и оставить).
- **Регистрация устройства** — не требует логина Apple ID для основного функционала; Apple ID запрашивается только при покупке/восстановлении.

## 📋 Что проверить перед отправкой

### 1. App Store Connect
- [ ] **Privacy Policy URL** — обязательная ссылка на политику конфиденциальности (добавить в раздел App Information).
- [ ] **Категория приложения** — выбрать подходящую (например, Productivity или Utilities).
- [ ] **Возрастной рейтинг** — заполнить анкету; для пересылки SMS обычно 4+.
- [ ] **In-App Purchases** — подписки созданы, цены и локализация заданы, статус «Ready to Submit».

### 2. Политика конфиденциальности и условия
- [ ] Разместить на сайте **Privacy Policy** и **Terms of Use** (или один документ с двумя разделами).
- [ ] В приложении: в Настройках пункты «Privacy Policy» и «Terms of Use» должны открывать **Safari/WebView** с этими страницами (сейчас там только заголовок; нужно подставить ваши URL и открывать через `Link` или `SafariServices`).

### 3. Контакт и поддержка
- [ ] **Contact Us** в настройках — ведёт на email или форму поддержки (сейчас только заголовок; добавить `mailto:` или ссылку).
- [ ] В App Store Connect указан **Support URL** и при необходимости **Marketing URL**.

### 4. Данные и разрешения
- [ ] В **App Privacy** (App Store Connect) указать, какие данные собираются (идентификаторы устройства, данные аккаунта и т.д.), если приложение что-то отправляет на сервер.
- [ ] Если используете только стандартные разрешения (сеть, без камеры/микрофона) — в Info.plist не нужны лишние ключи; при добавлении новых разрешений — добавить соответствующие ключи с описанием (например, `NSPhotoLibraryUsageDescription` при доступе к фото).

### 5. Функциональность и контент
- [ ] Онбординг и подписка работают без крашей в Release.
- [ ] Нет заглушек «Coming soon» для критичного функционала.
- [ ] Нет упоминаний цен/скидок вне In-App Purchase (если только не общие формулировки в описании приложения).

### 6. Guideline 5.1.1 (Data Collection & Privacy)
- [ ] Если собираете данные пользователя (email, телефон, device id) — в политике конфиденциальности это явно описано и есть возможность удалить аккаунт (реализовано через Delete Account).

### 7. Guideline 3.1.1 (In-App Purchase)
- [ ] Цифровой контент/функции доступны только через подписку, без обхода через внешние платежи.
- [ ] В настройках есть «Restore Purchase».

## Рекомендации по коду (опционально)

- **Privacy Policy / Terms / Contact** в `SettingsView` — заменить `Text("Privacy Policy")` и т.п. на экраны с `Link` на ваши URL или встроенный Safari (`SFSafariViewController`), когда будут готовы ссылки.
- **Тестирование** — прогнать сценарий: онбординг → подписка (sandbox) → добавление правила → пересылка SMS → удаление аккаунта.

После заполнения чеклиста и добавления ссылок на политику и условия приложение будет соответствовать типичным требованиям Apple для публикации.
